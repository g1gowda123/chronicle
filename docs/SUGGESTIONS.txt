3. SUGGESTED NEXT STEPS - ROLE B (GRAPH / STATE)
------------------------------------------------
3.1 Consume zone events
    VLM ZONE_CREATED / ZONE_RELOCALIZED events carry zone_id, label,
    similarity, prototype, and timestamp. Use zone_id as the room/place key in
    the graph instead of a free-text room name.

3.2 Consume action events
    VLM ACTION_VERIFIED carries action, object, confidence, evidence, accepted,
    source (llm/rule), timestamp, and clip correlation fields. Only apply an
    edge transition when accepted is true; route rejected actions to a review
    queue rather than dropping them.

3.3 Feed answer_query a 2-hop subgraph
    engine.answer_query(question, subgraph) accepts a NetworkX-like graph or a
    plain mapping. Keep the payload small: the entity, its last-known zone, and
    facts with real timestamps. GraphRAG rejects any citation whose timestamp
    does not exist in the payload, so never synthesize times.

3.4 Persistence ownership
    Zone prototypes are in-memory plus JSON in Role C. If the graph needs a
    single source of truth, persist Zone.to_dict() / match.as_event() in SQLite
    from Role B and reload Role C at start with the same prototype JSON.

3.5 Support relation names
    The template answer has phrasing for these relation families:
      RESTING_ON / ON / SUPPORTED_BY
      INSIDE / IN / CONTAINED_IN / INSERT_INTO
      PUT_DOWN / PLACED
      PICK_UP / PICKED_UP / HELD / HOLD
    Anything else is rendered verbatim ("the last recorded event for X was
    <relation> Y"), which is safe but reads awkwardly. Prefer the known
    relations when Role B writes edges.


4. SUGGESTED NEXT STEPS - ROLE D (UI / DASHBOARD)
-------------------------------------------------
4.1 Subscribe to the telemetry sink
    engine.on_event receives one dict per event with tag, kind, message,
    timestamp, and payload fields. The sink is already isolated: an exception
    in the dashboard cannot break ingestion (covered by a test).

4.2 Show the strip preview
    result.to_dict(include_preview=True) adds a data URL of the 1x3 strip.
    Use it in the review pane for rejected/low-confidence actions.

4.3 Surface provenance
    Every GraphRAG answer exposes source (llm/template), grounded, and
    citations. Show grounded=false distinctly; it means the answer had no
    verifiable timestamp and fell back to a template.

4.4 Latency
    Florence-2 and Ollama calls are blocking. Run verify_interaction in a
    worker thread or queue so the UI event loop stays responsive.

6. KNOWN LIMITATIONS
--------------------
  - Action classification is caption-then-text-classify, not a true VLM
    call. Swapping in a vision client only requires replacing
    ActionVerifier.chat_client; the schema and fallbacks stay the same.
  - The deterministic HSV embedder is for offline demo/tests only. It is not
    CLIP-quality and will not relocalize real rooms reliably.
  - GraphRAG grounds timestamps and zones but does not re-rank entities with
    CLIP text-to-node similarity yet.
  - Zone deduplication is exact-prototype based on an EMA; heavily occluded
    revisits may create a second zone. Tune CHRONICLE_VPR_THRESHOLD or
    CHRONICLE_VPR_MIN_MARGIN for real footage.
